# 1.4.26：真实发布回归与物流引用修复

日期：2026-09-19。本次延续 1.4.25 的动态类目填写，不是所有类目已经通过发布的声明。

## 修复

- 发货期不再依赖包装资料齐全；先滚动到实际区域，等待延迟生成的输入框，再填写来源数量上限与交期天数，提交前再次核对。隐藏副本不参与填写。
- 切换简体中文前，将来源属性与发布页稳定属性 ID 关联。读取组件名称中的属性 ID，并优先使用相同 ID 与精确名称，避免跨属性误用。
- 将 `Age/适用年龄` 与 `Age Range/年龄范围` 分开；依据真实发布字段 ID 识别 `Theme/场景`。修复 `4-6Y` 被匹配为 `4-6M` 的错误，严格区分年和月。
- 无输入框、需要点击“添加”的类目文本属性也可填写；来源没有值时不创建空行。
- 主图上传从物流区滚动回来后，允许上传菜单重新挂载并重新悬停。不会通过点击主图占位符误开图片银行。
- 成功发布结果保存当次页面接受的包装和物流属性。明确引用成功商品时，可补齐物流属性与运费模板；“仅补缺”保留目标已有资料。替换属性值时清除旧选项 ID。
- 空物流属性内容没有可见矩形时，仍检查其所在卡片。没有实际修复的物流资料不重复提交。
- 直接发布前检查库存是否小于起订量，明确显示两个数值；不会自行增加库存。保存草稿仍允许暂存此类商品。

成功标准是平台成功页及“成功提交，进入审核”回执，未把草稿成功算作公开发布，也未把进入审核算作审核通过。按这 10 件样本计算，取得成功提交回执的是 **2/10**，不能宣称 100%。

来源未公开或仅填写“Contact Us”的物理参数、实际库存、含电池/液体/磁性商品的运输属性仍需卖家核实。引用另一商品时，应选实际条件相符的商品；一个普货模板不能证明其他电子玩具同样属于普货。没有为了通过校验统一填假值或清空已有包装资料。

食品、服装等属于本地动态表单回归范围，本次真实账号测试限于其已开通的母婴与玩具叶子类目。尚未在客户双核 4 GB、Windows 10 1607 电脑上验证。主图视频入口不支持时仍可能降级为详情链接；详情上传沿用现有数量限制，不能声称来源全部媒体均已上传。
