# 1.4.40 桌面响应与后台任务隔离

## 原因与修改

发布、采集、Express API 和同步 JSON 持久化此前直接在 Electron 主线程运行。418 件商品的本地工作区约 47.80 MiB；整库复制、序列化和原子保存会占用窗口事件循环。任务结束后这些操作停止，窗口便恢复响应。

- 将本地服务完整移入独立 Worker，窗口、授权心跳、登录会话与系统加密仍由 Electron 主线程处理。仅通过受限消息桥访问这些接口。
- 跨线程保留授权校验、只读访问、人工验证进度及取消、暂停和退出时的保存行为。API 网关校验不变，密钥和会话仍经系统加密。
- 列表轮询不再携带原始采集快照、工作副本、完整发布历史、审计历史、HTML 和 SKU 明细。打开单品或批量编辑时按需读取完整商品。
- 只有任务状态变化时返回任务信息，避免再次发送未变化的商品列表。完整资料保存在原数据库，未删除或改写来源数据。
- 发布循环仅复制当前商品、任务和设置；合并单件发布准备和任务状态的持久化，去掉失败处理中的整库重复读取。

核对的两次六件批次均已结束，记录为两件经营类目未授权、四件库存低于起订量。这是批次停止的记录原因，与窗口阻塞分别处理；性能修复不改变真实的库存和类目条件。
