# 1.4.44 跨类目发布窗口恢复

## 问题证据与范围

1.4.43 的本机暂停诊断确认：目标为型号行的 `button.add-button`，命中遮挡元素为 `next-checkbox-input`、`next-select-menu-item`、`next-menu-item-text`。旧菜单关闭逻辑只识别两种容器，未识别这种 Fusion 选项列表。该逻辑由各商品类目共用，不能按手机型号单独修复。

本次在修改前检查了属性填写、规格填写、图片选择、物流窗口、提交确认、任务暂停、后台浏览器生命周期与前端任务展示。改动限定在这些共用交互路径及测试；未修改采集数据、商品事实属性、定价、库存、授权规则或数据库结构。没有更改用户当前商品或任务，没有重启正在运行的客户端。

## 最终变更

- `server/posting-popups.js`：统一识别 Fusion 选项列表、listbox 和已知属性菜单。按 `aria-controls` / `aria-owns` 确定选项归属；无归属且存在多个列表时不猜选项。支持门户列表外的搜索框。
- `server/publisher.js`：属性填写前收起遗留菜单；正在操作的菜单、图片与物流窗口保持打开；可关闭的上层通知独立处理；对话框内关闭下拉时不向父窗口发送 Escape。颜色、自定义规格和规格图片点击接入正常点击恢复。操作阶段在创建输入控件前更新，诊断能够标明当前字段。
- `server/posting-interaction.js`：文件选择事件在整个点击恢复阶段保持监听，点击派发后才开始等待文件选择器超时；结束或异常时移除监听，避免漏接、重复监听。
- `server/browser-error.js`：持续遮挡时显示实际字段名称，不向用户输出定位器和调用栈。
- `server/index.js`、`src/PublishPageView.jsx`、`src/PublishPageView.css`、`src/App.jsx`：暂停时尽力捕获当前发布视口，任务增加“查看暂停画面”。截图仅保留在本机内存，经现有授权 API 读取；不加入任务轮询数据或持久化商品数据库。窗口支持适应屏幕、原始大小、关闭及不可用状态。
- 版本升级为 1.4.44。

## 副作用与风险审查

- 不按类目名称判断窗口，不给不同商品填入臆测属性。控件的选项与实际回读值仍须匹配。
- 正在选择的父窗口不被恢复过程取消。普通导航菜单不识别为属性列表。
- 重试仍只限点击派发前的明确拦截；添加后的状态与提交后的平台回执仍须核对，不将未知回执当成成功。
- 国际站禁限售、侵权和人工验证提示不自动绕过；未知确认窗口不自动确认。
- 截图关联任务与当前商品，捕获期间页面变更则丢弃；捕获最长等待三秒。读取截图不启动、跳转或重建浏览器。密码输入框遮盖。
- 暂停画面是只读截图，不是远程控制界面；软件重启后旧截图不可用。恢复任务仍沿用已有断点逻辑。

使用本机已有卖家会话在独立浏览器中打开 DOOGEE 所属类目，国际站返回 `LOGIN_REQUIRED`。本次未能进入真实属性表单，没有保存真实草稿或提交商品。原客户端会话、暂停任务与商品库未修改。需在卖家窗口重新登录后继续验证。

## 安装与复现

1. 完全退出旧版抄得快，安装 1.4.44，核对原有商品和任务仍在。
2. 在卖家窗口重新登录国际站，再继续原暂停任务；观察型号步骤是否通过，核对结果以平台回执为准。
3. 在没有未完成任务的测试环境中，选取手机与服装、机械等实际经营类目的商品，先保存单件草稿。核对全部多选值、自定义规格、图片、物流设置及价格。
4. 遇到平台明确必填或图片限制时，检查保留原始业务原因。遇到新的暂停时，在最近任务点击眼睛图标“查看暂停画面”，检查时间、具体字段与画面；关闭窗口不改变任务进度。
5. 核对浏览器继续隐藏、任务栏没有发布窗口，已成功商品没有重复提交。
