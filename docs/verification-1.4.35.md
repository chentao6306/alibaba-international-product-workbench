# 1.4.35 采集属性与失败商品引用重构

日期：2026-09-19。分支：`codex/collection-mapping-1.4.35`。

## 使用流程

在「上架任务 → 失败商品处理」中按类目问题、必填属性或其他失败筛选，勾选待处理商品，点击「引用资料修复」。也可从商品工作台或批量编辑的类目页打开引用窗口。

引用来源包括本地成功发布记录，以及「读取当前卖家商品」保存的本地模板。后者需要用户在卖家窗口打开已有商品的编辑表单；它不是自动抓取全部线上商品的列表，也不把编辑表单当作已通过审核的证明。Electron 版直接读取其已登录的卖家窗口，网页版读取已有发布浏览器表单。读取不会提交或修改字段。

可选范围为完整类目模板、仅属性、仅规格与 SKU、仅报错必填字段。部分引用要求同类目。完整引用允许用户显式更换类目，预览显示类目、型号、属性和 SKU 新旧值；不会自动把早教书改为无人机配件。保存时再次核对预览版本，期间发生编辑则需重新预览。

默认保留匹配 SKU 的库存、编码和启用状态，新组合使用本商品总库存、空编码和启用状态。价格、标题、主图、详情和原始采集快照保留。包装、交期和物流资料仅在勾选后补充缺失项。引用保存模板快照及原失败记录，后续删除或编辑引用源不影响这批商品。

应用后点击「仅重试所选失败项」，使用右侧草稿/直接提交、间隔与销售方式设置。后端也会过滤已发布及成功草稿，避免重试队列重复提交成功项。暂停中的旧任务需继续或取消后才能新建重试任务。

## 数据与发布行为

- 采集阶段展开商品属性及包装区的延迟内容，合并结构化数据、可见属性和详情 iframe。记录读取是否稳定，保留属性 ID、值 ID、单位和冲突证据。
- 主视频、详情视频分别保留来源角色；保留详情模块顺序及重复图片。未把该数据改动宣称为平台详情视频上传功能。
- 卖家属性按 ID、精确名称及中英文别名匹配，冲突值不任意选取；多选控件清理旧选中项并读回核对。
- 支持实际存在的 Other 选项加自定义文本输入；没有可编辑输入时不把 Other 视为填充成功。
- 按实际发布表单缓存类目必填项，显示缺失、冲突、未检查或过期；缓存不把另一商品的已选值作为必填默认值。
- 识别 `属性[Type] 必须填写`、`属性[Logo printing] 必须填写` 和经营类目范围错误。单值规格修复同步 SKU，多值规格不自动合并。
- 卖家模板读取覆盖虚拟 SKU 表全部行；不完整读取拒绝保存。源码与原始采集数据不因引用被覆盖。
- 上架、失败重试仍只使用已保存资料，不访问来源商品详情补采。媒体按已保存地址下载上传。
