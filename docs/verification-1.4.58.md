# 1.4.58 规格识别与填写验证

日期：2026-10-05。

## 问题与修改

原逻辑把名称包含 `Color` / `颜色` 的所有维度都交给普通颜色控件处理。灯光颜色、镜片颜色等独立销售属性因此被跳过，随后又被误报为来源缺值。本次核对的四件车灯商品已在本地保存了完整的图片规格值，无需重新采集。

- 普通颜色与其他颜色维度分开识别；普通颜色图片不再借给同名选项的灯光颜色。
- 根据发布页属性 ID 优先匹配，名称只接受完整名称和明确别名；避免 `Color` 匹配 `Light Color`、`Size` 匹配 `Screen Size`。
- 识别直接渲染的必填规格，兼容没有规格选择复选框的页面；固定规格也可上传对应图片。
- 文本、原生下拉、多选、单选及现有组合框控件使用共用属性处理；整组写入、回读，清除旧多选，拒绝将多种 SKU 覆盖到单值控件。
- 根据实际目标维度名称和提交后的选项名称对应 SKU，保留源商品价格、库存及编码的对应关系。
- 只有同一属性 ID 下才复用选项 ID。来源确实有值但目标控件未接受时，报告未接受，不再误报来源缺失。
- 保留已有批量处理行为：单件失败后处理下一件，人工暂停仍有效。
