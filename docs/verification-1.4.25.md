# 1.4.25：动态类目属性与物流填写

本次针对“来源已有资料但发布页没有接受”“不同类目必填项不同”“包装资料填写后仍缺物流属性”等问题修订。版本号为 1.4.25，不包含 1.4.24 安装包或数据。

## 实现与边界

- 采集同时读取结构化属性和页面属性，保留属性 ID、值 ID、多选值、原产地和包装资料，识别更多属性与包装模块，过滤误读的分组标题。
- 发布时从实际表单读取必填状态、控件类型、属性 ID 和已选值。填写一个属性后重新读取表单，最多处理四轮联动字段，支持下拉、多选、复选和文本框，避免依赖固定品类字段清单。
- 优先按照属性 ID 匹配来源资料，并提供中英文名称映射。先检查类目必填项，再进行耗时的图片和详情填写；区分来源缺失与填写后未被页面接受。
- 缺少必填来源资料时，对原商品补采核对一次，并保留用户已编辑的信息。每个任务记录补采次数，避免无限重试；验证码和暂停沿用已有进度保留流程。
- 包装重量以 kg、尺寸以 cm 保存，按照发布控件单位转换，按长宽高计算体积。仅处理物流包装字段，避免改动净重或样品包装。保留已有有效值和部分来源资料，不再为了消除报错自动清空物流信息。
- 商品编辑增加“物流属性”输入。按用户或来源的明确资料选择发布页真实选项，并核对选择结果；不会自行把含电池、液体等商品标为普货。运费模板只能匹配用户提供的模板。
- 已填写部分包装时，在提交前检查完整包装与物流属性。草稿保存会保留未满足发布条件的提醒；草稿成功不代表可以直接发布。
- 账号未开通经营类目时，显示具体处理路径。缺少资料时保留字段清单，商品编辑界面可查看；不再自动拿未选择的其他成功商品填补资料。已明确选择的引用商品继续按引用规则处理。

Alibaba 官方的 [发布商品 Schema 说明](https://developer.alibaba.com/docs/doc.htm?articleId=119213&docType=1&treeId=456)也以类目字段、可选值和校验规则描述发布要求。本项目本次使用实际浏览器表单读取这些要求，没有接入开放平台发布 API。

食品、服装的新增用例是本地真实 Chromium 表单回归，不是所有线上类目逐一发布测试。未在客户的 Windows 10 1607、双核 4 GB 电脑上实测。平台未公开的商品资料、账号经营权限、验证码、网络和平台审核均不受本软件完整控制，因此本次验证不构成“所有商品 100% 上架”的保证。
