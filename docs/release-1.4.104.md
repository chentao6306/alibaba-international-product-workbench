# 1.4.104 图片编辑与详情兼容修复

日期：2026-11-11。状态：候选版。安装包和源码使用新版本号，不能覆盖已交付的 1.4.103。本记录不含客户商品、账号或诊断原文。

## 已确认的问题与行为变化

### 多商品图片编辑

此前商品切换入口较靠下，界面容易让用户以为只加载了第一件商品。现在把商品卡片、搜索、前后切换和当前商品标题放在图片编辑顶部；每页最多 12 件商品，每类图片每页 8 张。9 件商品可以在同一页选择，数千件商品不再展开成一个巨大的下拉框。

处理范围默认是当前商品，全部已选商品需明确切换；单张图片按钮只作用于当前商品的对应位置。跨商品复用水印修复区域需要显式勾选。图片处理最多并行 2 项，允许停止；停止后不启动后续请求，已完成结果保留，最多等待正在处理的两项结束。

图片草稿每批读取 100 件，保存每批 25 件，只传商品编号、版本标识和图片列表。撤销只保存变化部分，最多 20 步并限制估算大小，避免每次复制整个商品集合；超过预算时明确清除逐步撤销记录，本次编辑前恢复仍可用。服务端保存核对图片版本，防止覆盖同时发生的编辑。

### 删除详情图与恢复原图

已确认原问题：部分入口只修改图片列表或 HTML，原生图集仍引用旧图片，发布时因此检测到不一致。现在单商品、批量修改和图片专用接口都同步图片列表、HTML 以及原生详情图集。图集归属、标题、正文、表格与视频继续保留。明确记录过详情图片编辑的历史商品，在发布副本中按用户当前图片列表协调图集，不恢复用户删除的图片。

新增从采集原始快照恢复主图、详情图或全部图片。保存并重新打开后仍可恢复，不要求重新采集；恢复图片不覆盖当前价格、SKU、库存和其他编辑。原始快照必须完整且校验通过，缺失或被改动时说明原因，不能伪造“原始图片”。原文件已失效、超平台数量限制等情况仍需处理，恢复按钮不能保证第三方资源永久有效。

### 下载不完整与任务停止

此前同一组图片共用从启动时开始的 60 秒预算，排在后面的图片可能在开始下载前已耗尽预算。现在每张图片独立使用有界重试，保留已经成功的缓存；永久性 HTTP 错误不会无意义重试。有限工作队列和低内存限制继续生效。

任务暂停或本次发布结束时取消该次排队、重试等待与网络请求，下一件商品使用独立取消信号。失败证据包含图片位置、阶段、尝试次数和脱敏错误，不记录带鉴权参数的完整 URL。下载不全仍阻止提交，不能通过忽略图片提高表面成功率。客户“18 张只成功 15/16 张”的截图没有对应下载证据，本次修复的是代码中确认存在的预算问题，不能据此认定所有此类截图均为同一原因。

### 旧 HTML 与原始 FAQ 不一致

新收到的两件屏幕商品失败已用完整本地快照复现：历史 HTML 清洗后部分 FAQ 答案单元格为空，而来源快照和原生问答保留了完整答案，兼容转换完整性检查因此失败。

现在仅在完整原始快照校验、商品身份、HTML 来源摘要、问答顺序及当前问答内容均匹配时，补齐已证实由历史清洗产生的空单元格。不恢复用户改过或删除的问答，不猜答案，不绕过正文、表格、图片和视频的完整性检查。

## 维护与边界

涉及 `BatchImageEditor`、`batch-image-state`、`product-image-api`、`product-images`、`description-structure`、`description-compatibility`、`publisher` 和 `image-download-queue`。只读草稿验收工具补充了按已核实字段 ID 关联翻译后规格表头；生产 SKU 匹配规则没有放宽。

后台源码随版本分支保留，本版沿用 1.4.103 日志协议，无新增后台迁移。全类目自动化用构造数据覆盖，真实账号只能验证消费电子；医疗、服装、文具、鲜花、机械等类目的完整来源比较、发布和回读仍需对应账号证据。不能宣称跨类目 100% 成功或已完成客户全量发布验收。

本轮取消优化针对详情图片下载。既有原生视频下载的独立超时、本地图片压缩过程的取消响应不在本次优化范围；暂停仍可能等待该阶段退出。FAQ 自动补齐仅支持可唯一核实的双列问答容器，其他歧义布局继续拦截并保留资料，不能据此丢掉问答。三次新草稿和一次正式提交均为消费电子，本轮没有新增视频关联验收。

部署后优先核对受影响商品的小批次结果，再扩大使用；遇到新失败，客户日志应包含版本、叶类目、尝试编号、失败阶段与保存结果，避免只凭“页面操作未完成”猜测原因。
