# 本地服务状态与发布可靠性补充检查

日期：2026-11-09。本记录对应 1.4.98 归档后、1.4.99 候选版的修复，不代表此前交付的 1.4.98 安装包已包含这些修改。

## 已确认的故障

原界面将连接超时、后台退出、后台任务错误等统一显示为“连接或任务异常”。该提示不能证明客户外网中断。

本轮发现并修复一个进度恢复问题：`/api/state` 超时或无法连接时，界面会等待 Electron 的 `serviceStatus()` 返回；该 IPC 没有等待上限。如果桌面主进程也没有响应，状态刷新器一直保留同一个未结束请求，后续轮询无法重新读取已经恢复的 API。

`src/local-api.js` 现在将这次诊断等待限制为 1.5 秒。诊断失败、迟到或一直不返回均不会阻止下一轮进度读取；迟到结果不会覆盖后续状态。此恢复只读取进度，不重试任何保存或发布请求。

界面按实际证据区分“本地服务响应超时”“本地连接中断”“本地服务已停止”“后台任务已停止”“存储异常”“授权待恢复”和“进度读取异常”。HTTP 返回授权错误说明本地 API 已经响应，不再归为连接故障。

客户补充空闲时也频繁出现。检查发现即使没有任务，界面仍每 1.5 秒读取一次进度；桌面 API 中间件的授权检查和 `/api/state` 的卖家窗口状态原来都通过 `Atomics.wait` 同步等待 Electron 回复，单次最长 15 秒。桌面暂时无法回复会连带阻塞 API 事件循环及健康请求。这是可复现的软件阻塞路径，不能据此断定所有未知版本客户都触发了它。

桌面请求现在异步读取当次授权；状态接口异步读取卖家窗口状态，各自最多等待 2 秒，超时返回 503 和 `LOCAL_SERVICE_DESKTOP_TIMEOUT`。API 仍可响应健康请求，后续正常轮询可以恢复；界面显示“桌面连接响应超时”，不会把它当成外网中断或工作线程已停止。每次写入仍需要当次有效授权，不使用缓存许可；超时或迟到的旧回复不会放行新请求。保留原有只读授权和本地请求令牌检查。

随后通过独立线程发送健康请求，复现了另一处实际阻塞：原批量引用预览、资料计算和整库落盘同步执行，处理过程中 API 无法应答。大批保存结束后服务重新可用，不能把这一过程解释成客户断网。

引用 HTTP 路由现使用与原实现共享同一套生成器步骤的异步入口，按时间预算在商品间让出执行机会；磁盘临时快照分块异步写入。读取仍返回最后提交的完整状态，写完且刷新磁盘后才原子替换。另一个编辑、后台进度变化或外部文件替换发生时，保存返回 409 并保留更新的状态，不以旧预览覆盖它。更改单件商品的既有同步事务与其它发布路由未改成异步。

## 历史日志复核

本轮重新读取了客户报告，原文保存在私有数据目录，没有纳入源码：

- 一份 1.4.93 报告确认后台已停止，系统仍有约 4.96 GB 可用物理内存。旧记录没有工作线程退出原因，不能断定是网络、物理内存不足或运行时堆耗尽。
- 同一版本的批量引用报告有三次 `ERR_STRING_TOO_LONG`。这与整批商品序列化成单个大字符串有关，当前 `server/reference-workflow.js` 已按商品生成摘要并分页预览。不能把这三次错误直接当成另一份报告中后台退出的原因。
- 一份 1.4.85 报告上传时后台仍运行，并有页面操作超时及属性映射失败。不能把不同时间发生的控件失败合并为服务宕机。
- 最新橙色状态截图没有版本和日志，不能据此确认客户已经运行当前修复，也不能确认该次退出原因。

## 发布链路的限制

本轮也修复了已确认的自定义属性长名称问题，见 [长名称记录](custom-attribute-name-2026-11-09.md)。规则模式独立可用，不依赖 AI。

首次尝试对以前获提交回执的消费电子商品只读回查，隔离会话已转到登录页，在身份核验处停止。恢复本机缺失的同版本 Electron 运行文件后，使用获授权的桌面加密会话重新核验身份，已完成该件消费电子商品发布后编辑页的只读验收：标题、6 张主图、两种颜色、三档价格及起订量、必填属性和 11 张详情图检查通过。测试没有重新保存或提交。本次使用旧版详情，不构成医疗类目、新版详情或双视频验收；主图/详情图片计数通过也不等同于所有图像像素逐一比对。

医疗、文具、塑料瓶、服装、鲜花、灯具和消费电子的自动回归不能代替各自账号的真实草稿、正式发布与平台回读。没有客户日志的冰衣机“页面操作未完成”仍待定位。候选状态保留；不要以删除来源字段、猜测必填值或重复提交来提高表面成功率。
