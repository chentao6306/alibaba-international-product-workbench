# 1.4.49 来源链接、规则确认与验证窗口

## 影响分析与范围

修改前检查 Electron 来源链接 IPC、卖家窗口复用及显示顺序，发布设置持久化、AsyncLocalStorage 策略隔离、提交回执、失败修复和暂停分类，以及采集与来源详情的验证码备用浏览器生命周期。

本轮修改：

- `electron/main.js`、`electron/source-navigation.js`：来源窗口在加载前显示；直接进入商品链接，避免先加载卖家首页。ERR_ABORTED 后等待真正提交并就绪的页面；网络错误、关闭、崩溃和超时仍保留错误。新请求结束旧请求的监听和计时器，避免连续点击产生过期报错。URL 限定 HTTP(S) 国际站商品链接且不接受用户名密码。
- `server/posting-policy.js`、`server/publisher.js`：正式提交前确认已识别的 `.sales-range` 规则复选框；仅严格启用设置时自动勾选，回读确认已选中。明确收到对应校验错误后，允许补确认再提交一次；未知回执不重试。草稿不自动确认。控件缺失、歧义、禁用或未接受勾选时暂停。
- `server/native-browser-window.js`、`server/browser-runtime.js`：保留原验证码会话，通过 CDP 获取该浏览器 PID，仅隐藏该 PID 的原生 Chromium 窗口。恢复验证时重新显示。不按进程名批量操作，不关闭用户其他浏览器。
- `src/PublishingRiskSetting.jsx`：现有启用确认说明补充“禁限售规则确认项”。版本为 1.4.49，依赖不变。

本轮未改动授权服务、价格库存、商品资料、类目选择、引用逻辑或任务队列。

## 原因与平台证据

来源链接旧逻辑在 `loadURL()` 成功后才显示窗口。页面替换跳转会拒绝原加载 Promise，出现 ERR_ABORTED；已有可见窗口可能仍显示详情，隐藏窗口则未执行显示步骤。

实时读取国际站 `main-cgs/7.1.115/publish-splitpacking.js`，SalesRange 组件根据服务器 `riskCheckData.countryList[].needStrongWarn` 决定是否渲染 `.sales-range` 和复选框。`isNeedStrongWarn && !isCheckCountry` 会生成 `submitTipWhenNotConfirmRisk` 校验错误。实时响应文案：

- `commonStrongWarnTip`：请确认《阿里巴巴国际站禁限售规则》。
- `submitTipWhenNotConfirmRisk`：请确认已充分了解《阿里巴巴国际站禁限售规则》再提交表单。
- 英文同一字段为 Alibaba International Station Ban and Restriction Rules / Restriction Rules。

现有逻辑只处理风险弹窗，没有覆盖此独立规则字段。相同浏览器版本不能保证服务器返回相同风险数据；客户账号上的实际触发条件尚未直接复现，不声称已确认两台电脑差异的全部原因。

验证码备用流程完成后保留 headed Chromium 会话，原隐藏逻辑只调整窗口坐标到屏幕外，仍有任务栏入口。新处理使用 Windows 隐藏窗口，保留正常视口和验证状态。

## 副作用与限制

来源链接仅等待导航结果，不修改采集资料。规则处理不更改目标国家、证书、价格或其他商品字段，不把勾选当成发布成功；硬拒绝和人工验证继续保留原处理。响应不明时仍暂停以避免重复发布。

Windows 隐藏操作限定当前浏览器 PID，串行执行隐藏/显示，并设置进程超时。若客户系统限制 PowerShell/Add-Type，原屏幕外隐藏仍生效，但任务栏图标可能保留；采集不会因此关闭会话。普通 headless 采集与发布不调用原生窗口操作。

## 手动验证

1. 等正在进行的任务结束，退出旧客户端并安装 1.4.49。确认原商品和任务保留。
2. 打开商品编辑页，点击产品链接，确认窗口立即显示；连续点击和详情跳转不应产生 ERR_ABORTED 错误提示。断网时应仍提示真实加载失败。
3. 客户电脑保持风险开关开启，对原先提示“请确认禁限售规则”的失败商品重试。出现该字段时，应确认勾选后继续，最终只以平台成功回执判定成功。已发布成功的商品不要重复提交。
4. 开关关闭时不自动勾选；平台明确禁止时仍停止。保存草稿不触发正式发布。
5. 采集触发验证码时人工完成；窗口隐藏后任务栏不应继续留该自动化窗口图标，任务应继续。再次触发验证码应能重新显示。其他 Chrome 窗口应保持原状态。
