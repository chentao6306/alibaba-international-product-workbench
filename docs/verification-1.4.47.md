# 1.4.47 跨类目属性冲突、语言恢复与风险提示设置

## 影响范围

用户确认先修复并验证属性冲突，再交付安装包。修改前检查了采集合并、发布前补全、类目属性绑定、实际填写、补填、回读校验、引用预览保存及打包入口。

- `server/publish-reference.js`：将 Function/功能与 Feature/功能/特性分为独立别名组。采集、补全、SKU 键及单字段引用沿用同一规则。
- `server/category-attributes.js`：宽泛别名不能绑定到已有精确名称匹配的字段；已观察到的用途属性 191288357 保留原生 use 名称。明确属性 ID 仍优先于名称，详情字段仍低于类目字段。
- `server/attribute-values.js`：识别经数值换算验证一致的英寸/厘米括号表达，并处理明确的电容触摸屏尺寸后缀。不接受矛盾的括号尺寸。
- `server/publisher.js`：删除会交叉填写功能、特性的旧路径，交给统一类目字段写入；已被属性 ID 排除的值不能通过补填回退重新写入另一个字段。
- 版本文件升至 1.4.47；依赖版本未变更。

同时包含此前已完成但尚未交付 EXE 的修改：

- `src/PublishingRiskSetting.jsx`、`src/App.jsx`、`server/index.js`、`server/store.js`、`server/posting-policy.js`、`server/publisher.js`：风险提示继续上架开关，默认关闭、启用确认、持久化、每次发布独立策略、记录提示确认，避免重复确认。平台明确拒绝、人工验证及未知提交结果仍停止或暂停。
- `server/posting-language.js`、`server/publisher.js`：页头中文但正文英文时重新选择真实语言菜单；只在填写前允许一次原地址刷新；保留验证等待、取消和登录失效处理。

本次没有修改授权服务、任务调度、库存及价格策略、物流策略、已保存商品资料或原客户端数据。没有自动用成功商品覆盖实际型号、尺寸或功能。

## 问题与修复效果

1. 智能手表的功能/特性 191284141 与功能 210194090 原来被归入同组，导致冲突或两个字段填入同一值。现在分别填写 Touchscreen/with earphone 和运动、心率等功能。
2. 平板的 Feature=Hard 与 Function=5G/4G/WIFI/BT/FM/GPS/Record/rfid 不再合并。只有对应的 Feature 写入平台特性，其他来源资料保留。
3. 平板 11 inches 与 11 inches(27.94cm) 被确认等价；11 inches(30cm)、不一致单位及不同尺寸仍判为冲突。
4. 充电器的原生 use=For drone 与来源补充 Usage 不再同时绑定到同一个明确的 use 字段，无需引用模板即可通过本次用途校验。
5. 仅引用“功能/特性”不会同时覆盖“功能”，反之亦然。预览不落库，保存保留其他字段、价格和库存。
