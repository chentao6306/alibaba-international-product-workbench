# 1.4.102 候选版记录

日期：2026-11-09。源码分支 `codex/1.4.102`，继承 [1.4.101](release-1.4.101.md) 的完整客户端、本地服务、授权后台、官网和构建源码。此次集中修复换类目后重复规格无法恢复的问题；规则模式直接生效，无需 AI。

## 新客户日志确认的问题

1.4.100 客户日志中，一件商品在打开目标类目时被上一商品的草稿跳转打断。原始异常明确显示新类目导航遭旧草稿 `itemId` 跳转中断。1.4.101 的每件商品独立页面和新页面身份检查已覆盖该原因，本版继承；不能据此断言截图另外两件没有完整记录的“页面操作未完成”也是同一原因。

另一件商品有 25 个 SKU，其中两组颜色显示名称重复，各自的来源选项编号、图片和价格不同。客户更改目标类目后，编辑器按设计清除旧类目的字段 ID 和选项 ID；旧版本恢复重复选项时只读取当前规格编号，因缺少编号而拒绝。原始来源快照和每行 SKU 的组合编号仍完整，足以核对真实对应关系。这一缺口在 1.4.101 仍可复现，不把升级旧候选包当作已解决。

## 修复边界

当当前规格没有字段编号时，仅在来源快照、商品身份、唯一规格、完整选项以及逐行 SKU 编号和原始组合相互一致时，内部使用来源编号恢复重复标签。恢复后的工作规格仍不携带旧类目字段编号，目标字段与选项继续按当前发布表单重新匹配。

价格、库存、编码、启用状态和图片继续使用当前编辑值；不以来源快照覆盖用户商务资料，不减少或合并 SKU。来源冲突、手动改变规格语义、缺失组合证据等情况仍明确拒绝，避免错价或串图。

诊断重放工具现在支持“规格身份无法确认”的记录，并把日志单独保存的来源快照还原到原有模型边界；不会把当前编辑资料误当原始来源。实际客户资料仍仅在私有目录使用，测试提交构造夹具。
