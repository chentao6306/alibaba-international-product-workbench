# 1.4.41 属性采集与发布匹配修复

## 已确认的问题

- 本地失败商品已经采集 `output power` 和 `multi-function integrated`，但发布页中文字段没有对应别名，导致误报缺少输出功率、多功能一体化。
- 旧选项匹配只比较数字，可能把 `LTE, 5 G` 当成单个 `5G` 选项，导致多选填写或读取结果校验错误。
- 同一商品中的屏幕范围与具体尺寸、电池容量范围与具体容量被按文本差异判定冲突。
- `cpu: Deca Core` 与 `CPU: Snapdrtagon 8 Gen3` 含义不同。采集合并及发布入口按属性名去重可能混合或覆盖核心数，随后误报冲突。
- 只有 `Fujian` 的原产地来源被当作已采集完整国家，最终错误归类为页面未接受。

## 修改

- 增加充电器已确认字段的中英文对应关系，旧商品直接使用新映射。
- 统一属性值比较：完整文本、单位和数值区间一起校验；模型名称或网络列表不会仅因数字相同而匹配。多选支持旧的逗号拼接字符串及数组，并逐项核对实际选中值。
- 屏幕和容量选择能被所有来源范围包含的实际来源值，不生成新的交集数值。识别明确的屏幕、锂电池文字后缀；互不相容的数值及边界差异保留冲突。
- 区分已识别的处理器核心数和型号；发布入口保留来源属性行，由字段解析器处理一致性。未知处理器信息和矛盾核心数仍需核对。
- 支持明确的 `Mainland China`、`China (Mainland)` 国家名称；仅有省份的资料归类为缺少国家，不猜测产地。
- 保留来源快照、商品商业数据、实际必填项、图片校验和禁限售风险处理。包含此前后台发布、物流默认项及桌面线程隔离修改。
