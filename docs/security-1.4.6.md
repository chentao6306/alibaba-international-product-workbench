# 1.4.6 安全加固与验证记录

日期：2026-09-11。范围：本仓库桌面客户端、本地 API 和自有授权服务器 106.55.45.126。未扫描第三方平台，未进行生产拒绝服务或密码爆破测试。

## 已修复

- 授权服务此前主要依据账号名和设备信息签发客户端会话，缺少服务器能独立核验的客户凭据。新增 256 位随机软件授权码，数据库只存 SHA256 哈希，比较使用恒定时间函数。新账号默认启用，旧账号支持逐个迁移。
- 管理员会话新增数据库记录与密码指纹校验，登出可以立即撤销；授权码重置、账号停用和注销使旧客户端会话版本失效，恢复账号不会恢复旧会话。
- 客户端固定使用 HTTPS，限制授权地址、禁止重定向，不忽略证书错误。管理端禁止明文提交凭据。登录脚本外置并应用 CSP，本地 API 在解析业务请求前检查授权。
- 软件授权码使用 Windows 系统凭据加密能力保存，不回传到渲染页面，支持下次启动复用。修复退出时直接终止进程可能影响 Chromium 加密状态落盘的问题。
- 已有的服务器时间授权租约、持续心跳、本地接口鉴权、API 密钥加密、ASAR 完整性校验和 Electron 安全开关保留并验证。

## 安全边界与待办

1. **旧账号迁移仍需运营执行。** 为保留旧客户端可用性，没有自动为所有现有客户启用授权码。后台显示“授权安全待升级”的账号仍存在仅凭账号信息申请授权的风险。先升级客户到 1.4.6，再启用并交付每个账号的授权码。全部迁移后关闭明文客户端兼容入口。
2. **无法保证不可逆向。** 客户拥有本机管理员权限时，能够分析或修改本地程序；压缩、ASAR 与完整性校验提高修改门槛，不等于源代码保密。采集和上架核心逻辑仍在客户电脑运行；若要求核心源码不下发，需要另行设计服务器执行方案，并评估客户数据与浏览器会话的边界。
3. **安装包没有商业代码签名。** 已启用未来更新的签名校验配置，但当前 `Get-AuthenticodeSignature` 仍为 `NotSigned`。正式签名需要企业代码签名证书；不要把构建工具日志中的 signing 当成已签名证明。
4. 本次检查不能证明服务器不存在所有漏洞。运行时依赖审计没有覆盖所有操作系统、浏览器或第三方依赖的未来漏洞；持续更新、备份和访问审计仍有必要。新授权码应按凭据保管，不公开发送。
