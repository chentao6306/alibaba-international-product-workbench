# 1.4.33 随机上架间隔与属性菜单收起修复

日期：2026-09-19。分支：`codex/publish-overlay-fix-1.4.33`。

## 修复内容

本地代码核对发现，上架任务在资料不完整时会先补采源商品，因此上架过程中报告的人工验证可能来自源商品采集。发布页也调用同一验证检测逻辑，不能只凭“正在上架”就判断验证码来自哪一页。本次没有取得真实发布验证码现场，不将其认定为已证实的发布页验证码，也不保证现有检测绝无误判。

用户截图中的“Android 14”是属性选择下拉菜单，截图没有显示验证码。原有选项填写只按 Escape 收起菜单；本地浏览器复现了选项已选中但菜单忽略 Escape、遮挡下一步操作的情形。现在确认选项提交后尝试 Escape、移开焦点及点击无操作的字段标签收起已知属性菜单，并再次读取所选值。真正模态弹窗仍保留检查，不会仅因为包含列表就忽略。本次未在客户实时页面复现原始错误，截图不能确认其实际 DOM 结构。

上架任务新增“商品间随机上架间隔（秒）”设置，用户可选择最短和最长等待时间（0 至 300 秒）。第一件直接开始，后续商品补采及发布前随机等待，界面显示倒计时；0 至 0 关闭等待，相同值为固定间隔。开始或继续任务时保存设置，暂停时可修改，既有成功回执不会重放。已有任务无设置时保持原来的速度。

间隔等待不计入页面无进展超时；每 250 毫秒检查暂停请求。恢复到第二件以后的商品时重新按当前设置等待一次，同一商品内部自动修复不反复加等。此功能只调节操作间隔，尚未实测其对验证码触发率的影响，出现真实验证仍须人工完成。
