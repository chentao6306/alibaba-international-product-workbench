# 1.4.46 属性回读、产地、颜色规格与引用验证

## 影响范围与原因

修改前检查了来源采集、属性合并、字段映射、发布前校验、颜色规格图片、引用预览保存、任务结果与测试入口。

1. 型号、产品类型、功能等文本字段接收数组时，填写值和校验值的逗号空格格式不一致，导致内容已填写却被报告“发布页未接受”。
2. 来源页面将 `Fujian` 放在产地字段，国家映射不能识别，导致错误报告缺少产地。
3. 通用属性填写先把 `Picture, Blue`、`Dark Gray` 等描述值填进颜色，规格流程再添加真实 SKU 的 `Blue`、`Dark Grey`，形成没有图片的额外颜色。草稿保存可以成功，但正式发布仍会校验颜色。
4. 详情表格和平台类目属性共用 `dom` 来源标记，同名值被合并；属性值内的展开控件还可能被误读为新的属性。

本次代码修改限定在这些路径、相关验证工具、测试及版本文件。沿用现有完整引用功能，没有增加自动随机选取模板，没有修改授权、任务调度、定价、库存策略、物流策略及客户端自动更新逻辑。

## 最终变更

- `server/attribute-values.js`、`server/publisher.js`：统一数组写入文本的格式，并对完整文本回读进行比较；下拉、多选控件继续逐值校验，缺值、额外值或不同型号不能通过。
- `server/origin-country.js`：将明确的中国大陆省份名称转换为发布表单需要的国家；未知地址及冲突国家仍不猜测，原始采集快照保留。
- `server/publisher.js`：已有 SKU 规格组的颜色由规格流程统一填写，通用属性和必填修复不再追加描述中的颜色。
- `server/category-attributes.js`、`server/source-description-frame.js`：区分类目属性、页面详情表格及详情 iframe；类目属性优先，详情字段只补充缺项；去除展开按钮噪声，保留详情正文、原始声明及旧版表格、包装数据。采集属性版本升为 6。
- `test/reference-workflow.test.js`：复现截图中的手机引用，从 64 个 SKU 替换为 96 个，验证预览不落库、保存后清除旧省份/型号/属性/选项 ID、发布准备不恢复旧数据，价格与原始快照保留。
- `tools/publish-workflow-qa.mjs`、`tools/verify-live-posting-attributes.mjs`：在独立副本中运行生产发布 API，记录阶段、真实回执与颜色规格；支持真实来源重新采集对比。

## 手动验证

1. 完全退出旧客户端后安装 1.4.46，核对版本号和原商品、任务仍在。
2. 在卖家后台按上述新商品 ID 查看六次正式提交及其审核状态，避免再次上架同一件测试商品产生重复。
3. 在本软件选中需要修复的失败商品，打开“引用成功商品资料”，选择已核对的参考商品及“完整引用”，先预览型号、省份、属性和 SKU 新旧值，再保存。
4. 重新打开商品，确认旧值未残留；使用草稿核对规格图片、属性、价格及描述，核对后再发布。
5. 对重新采集的手机检查属性中没有 `Show more` 假字段，详情声明及图片仍完整；真正缺资料或被平台拒绝时应显示对应原因。
